# Handoff Fox vision

Handoff Fox makes a Linux machine feel like part of your Mac workspace. Open the desktop where you left it, move a file without hunting for an address or folder, or pick up a saved project from the menu bar.

## Who it’s for

Start with people who use a Mac every day and keep a Linux desktop, workstation, or SSH host for development, research, or automation. A Hyprland desktop is the first target for remote viewing. Headless hosts should still be useful for transfers, projects, and approved jobs.

## What earns a place in the fox

- **Get back to work quickly.** The first-time target is two minutes from SSH readiness to opening the Linux desktop. Returning users should be able to resume a saved desktop in one click. Test each action on each supported setup.
- **Show where things went.** Name the destination before sending. Show delivery after the receiver confirms it. Keep the retry beside the transfer.
- **Keep the companion small.** One fox in the Mac menu bar and the Linux tray. Use short reactions to show meaningful changes and keep the same information available with Reduce Motion.
- **Make Linux useful from the Mac.** Let people start approved jobs, leave, and come back to the same run, exit code, and artifacts. Keep agent integrations optional so ordinary desktop and file actions work on their own.

## What the pilot should prove

Give five Mac-and-Linux users the same file to send. Ask them to find the delivered copy and recover from an interrupted send without coaching. Keep the motion if at least four understand both states. Revisit a live CLI session row if at least two people can identify which sample session needs them and name a recurring multi-session workflow it would help.

Use the [comparison preview and pilot script](previews/fox-motion.html) to test that choice. The [roadmap](docs/ROADMAP.md) tracks what to build and how to verify it.
